# C 端账号与会员

核验日期：2026-11-27。范围：`c-server`、`c-h5`、`c-app`（H5 模式）。admin-server 与 admin-web 未改动。

## 数据表

`c_user` 由 `c-server/c-bootstrap/src/main/resources/db/schema.sql` 创建，可重复执行。开发环境用 Spring SQL 初始化（`spring.sql.init.mode=always`），每次启动执行 `CREATE TABLE IF NOT EXISTS`；生产默认 `SQL_INIT_MODE=never`，由发布流程执行同一脚本。

```sql
CREATE TABLE IF NOT EXISTS c_user (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    phone         VARCHAR(32)  NOT NULL,
    password_hash VARCHAR(100) NOT NULL,
    nickname      VARCHAR(64)  NOT NULL DEFAULT '',
    avatar        VARCHAR(512) NOT NULL DEFAULT '',
    status        SMALLINT     NOT NULL DEFAULT 1 CHECK (status IN (0, 1)),
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_c_user_phone ON c_user (phone);
```

关联的 `pm_member` 由 admin-server 维护，C 端只读，按 `phone` 关联：

```sql
SELECT id, member_no, username, nickname, phone, level, points, balance, status, joined_at
FROM pm_member
WHERE phone = :phone AND deleted = 0
LIMIT 1;
```

代码位置 `CMemberService` 已标注：

```text
shortcut: 跨服务共享表，拆微服务时改为调用 admin API。
```

## 接口

统一响应沿用 `c-common` 的 `R`：成功 `code=0`，失败 `code=-1`，`bizCode` 为机器可读错误码，HTTP 状态使用真实语义。注册与登录参数用 Jakarta Validation 校验。

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/c/auth/register` | 否 | 手机号 + 密码注册 |
| POST | `/c/auth/login` | 否 | 登录，返回 access token，并写 `c_refresh` Cookie |
| POST | `/c/auth/refresh` | refresh Cookie | 换新 access token |
| POST | `/c/auth/logout` | refresh Cookie | 撤销 Redis 白名单并清 Cookie |
| GET | `/c/user/info` | Bearer | 当前 C 用户 |
| GET | `/c/members/me` | Bearer | 按手机号关联的会员档案 |
| GET | `/health` | 否 | 保留的健康检查 |

注册请求：

```json
{"phone":"13900000001","password":"Test123456","nickname":"张三"}
```

登录响应（refresh token 只在 HttpOnly Cookie 中，不进入 JSON）：

```json
{
  "code": 0,
  "data": {
    "accessToken": "<JWT>",
    "user": {"id": 1, "phone": "13900000001", "nickname": "张三", "avatar": ""}
  },
  "error": null,
  "message": "ok"
}
```

错误码：

| bizCode | HTTP | 场景 |
|---|---|---|
| `VALIDATION_ERROR` | 400 | 手机号格式、密码长度等参数错误 |
| `INVALID_CREDENTIALS` | 401 | 手机号不存在或密码错误 |
| `REFRESH_TOKEN_INVALID` | 401 | refresh 缺失、签名无效、已登出或已过期 |
| `UNAUTHORIZED` | 401 | 未带 access token 或 token 无效 |
| `USER_DISABLED` | 403 | `c_user.status=0` |
| `MEMBER_NOT_FOUND` | 404 | 手机号没有对应 `pm_member` |
| `PHONE_ALREADY_REGISTERED` | 409 | 手机号已存在（唯一索引兜底） |

## 与 admin 的隔离边界

| 项 | admin-server | c-server |
|---|---|---|
| 端口 | 5320，context-path `/api` | 8081，无 context-path |
| JWT access 密钥 | `JWT_ACCESS_SECRET` | `C_JWT_ACCESS_SECRET` |
| JWT refresh 密钥 | `JWT_REFRESH_SECRET` | `C_JWT_REFRESH_SECRET` |
| issuer | `premium-member-admin` | `premium-member-c` |
| refresh Cookie | `jwt`，Path `/api` | `c_refresh`，Path `/c/auth` |
| refresh Redis key | admin `TokenStore` | `c:refresh:<jti>` |
| Redis DB（开发默认） | 0 | 2 |
| 账号表 | `sys_user` | `c_user` |
| 会员表 | `pm_member` 读写 | `pm_member` 只读 |

两套服务不共享 Maven 模块、JWT 密钥或 issuer。admin token 无法通过 c-server 的签名与 issuer 校验，反之亦然。C 端没有角色/权限模型，只区分登录与未登录。

## 启动顺序

```bash
# 1. 依赖：PostgreSQL 15432、Redis 16379
cd deploy && docker compose up -d

# 2. c-server（首次启动自动建 c_user）
cd ../c-server
export DB_PASSWORD=premium_member_dev_only
export REDIS_PASSWORD=premium_member_dev_only
export C_JWT_ACCESS_SECRET="$(openssl rand -base64 48)"
export C_JWT_REFRESH_SECRET="$(openssl rand -base64 48)"
jenv exec /Users/hanson/work/Env/apache-maven-3.8.8/bin/mvn -q -DskipTests package
jenv exec java -jar c-bootstrap/target/c-bootstrap-0.1.0.jar

# 3. c-h5 → http://127.0.0.1:5174
cd ../c-h5 && npm install && npm run dev

# 4. c-app H5 → http://127.0.0.1:5173
cd ../c-app && npm install && npm run dev:h5
```

新库没有 C 端账号时，先注册一个与 `pm_member.phone` 相同的手机号：

```bash
curl -sS -H 'Content-Type: application/json' \
  -d '{"phone":"13900000001","password":"Test123456","nickname":"张三"}' \
  http://127.0.0.1:8081/c/auth/register
```

关键环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `C_SERVER_PORT` | `8081` | c-server 端口 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `127.0.0.1` / `15432` / `premium_member` | 仅 dev profile |
| `DB_USER` / `DB_PASSWORD` | `premium_member` / dev 默认值 | 生产必须覆盖 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | `127.0.0.1` / `16379` / 空 | dev 默认无密码时按 application.yml |
| `REDIS_DATABASE` | `2` | 与 admin 的 DB 0 分开 |
| `C_JWT_ACCESS_SECRET` / `C_JWT_REFRESH_SECRET` | 无 | 必须 ≥32 字节；禁止复用 admin 密钥 |
| `C_JWT_ACCESS_TTL` / `C_JWT_REFRESH_TTL` | `2h` / `30d` | token 与 Cookie 有效期 |
| `C_COOKIE_SECURE` | `false` | HTTPS 部署设 `true` |
| `SQL_INIT_MODE` | dev `always` / prod `never` | 是否启动时执行建表脚本 |

## 未验证与已知限制

- c-app 只实测 H5 模式；`dev:mp-weixin` 与 App 真机未运行（微信开发者工具、HBuilderX 未在本次验收环境启动）。
- 未运行 admin-server，因此“admin token 调 c-server 返回 401”没有做在线交叉请求；隔离依据是不同密钥、不同 issuer、不同 Cookie 名与 Redis key，已在代码和配置核对。
- refresh token 不旋转；登出撤销 Redis 白名单，但已签发的 access token 仍可用到 2 小时过期，C 端未做 access 黑名单。需要更严格撤权时再加。
- 生产环境不会自动建表，需要发布流程先执行 `c-server/c-bootstrap/src/main/resources/db/schema.sql`。
